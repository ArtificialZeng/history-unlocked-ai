# Generic indexed-cell controls v1

The package decodes and encodes the registered fixed injective indexed-cell relation. It returns an ordered token array. It does not tokenize raw text, score languages, inspect sources, fit keys, or establish historical applicability.

The frozen inputs are controls.json (three literal input pairs, explicit gold token lists, and occurrence certificates), refusal_controls.json (30 literal refusal cases), validation_config.json (bounds and deterministic settings), and preimplementation_lock.json (their hashes and actual lock time). SYN-01 and SYN-02 include repeated tokens and multi-digit positions. SYN-02 distinguishes U+00E9 from U+0065 U+0301. SYN-03 covers every cell of a 30-token alphabet and keeps I, J, and IJ distinct. Alphabet, display, and ciphertext group orders differ in the fixtures.

The API is decode(alphabet, ciphertext) and encode(alphabet, tokens) from kernel.mjs. The alphabet is an array of exact records with cell_id and token string fields. The ciphertext is an exact record with length and groups; each group has cell_id and indices. Length is explicit, so a missing last position cannot be silently hidden by taking the largest observed number. The encoder accepts only a token array and emits every alphabet cell, including empty groups. Both functions leave their inputs unchanged.

IndexedCellValidationError carries a stable code and details. The fixed refusal controls distinguish missing_indices, duplicate_index, zero_index, negative_index, noninteger_index, out_of_range_index, unknown_cell, duplicate_token_label, duplicate_cell_id, and duplicate_group_cell, and cover malformed lengths, null/empty tokens, a raw string, unsafe integers, unknown empty cells, extra fields, and an accent variant outside the alphabet. There are no nulls or position exceptions. Code details identify the offending path or missing ranges.

independent_verifier.mjs exports verifyPair(alphabet, ciphertext, candidateTokens, optionalCertificate). It imports no kernel and writes nothing. It checks the complete membership relation and independently constructs an occurrence certificate from the supplied candidate. verify_frozen_controls.mjs exports verifyFrozenControls(), a separate read-only audit of the prewritten gold pairs with no kernel call. run_validation.mjs exports runFrozenValidation(), the bounded fixed-control/refusal/enumeration runner. These modules use only built-in Node libraries and files in this package. A caller may save the returned report. No terminal, Git, external service, registry, or historical data is required.

In a JavaScript environment with top-level await and Node built-ins, import this directory's run_validation.mjs and call runFrozenValidation(); import verify_frozen_controls.mjs and call verifyFrozenControls() for the separate read-only audit. Both verify the frozen SHA-256 locks before evaluating controls. No writes occur within either runner. MATHEMATICAL_SPEC.md states the uniqueness and forward/inverse proof.

The registered main run is bounded by 4,800 kernel calls and 4,400 verifier calls. The main run uses 4,768 kernel calls and 4,396 verifier calls if all registered cases complete. The separate three-fixture read-only audit brings the cumulative verifier total to 4,399. Enumeration uses all 364 token vectors over the frozen three-token alphabet for lengths 0..5, six group orders and two internal index orders: 4,368 decoder/verifier calls, including redundant index-order variants for some short/empty lists. It is mathematical/software validation, not an authentic-language control or evidence of historical success.

The package is a neutral reusable resource. An eventual source may use a different rule. Independent source review must establish applicability before any historical execution or claim. A software PASS has only the stated synthetic/software scope.
