## What the current inventory establishes

The [dated HC Portal refresh](CATALOGUE_REFRESH.json) parsed 1,875 rows through
`data.data`, including 1,047 marked Not solved. All these IDs were already in the
controller registry; this is not worldwide source exhaustion, a count of
attempted attacks, or evidence that all registered items are solved. HC615
remained Solved. Its attribution is documented in the earlier public excerpt.
The first envelope-schema assertion failed; the corrected cached parse required
no additional request. Failed observations remain recorded rather than becoming
false empty results.

The public registry now retains **2,568 identities**, including three additions in
this release and 47 since code-core-v3. Access routes and collection leads count
as identities, not independent messages. The 47 main rows and 1,480 screening rows
are administrative totals.

## Portable code added

The [static-loader tracer](catalogue_metadata/static_loader/README.md) uses AST
object identity to retain distinct nested calls sharing an offset. Four existing
synthetic controls passed after a single generic repair. Its bounded traversal
does not execute page code, fetch data, infer dynamic URLs, or read inline payload
values. These are software controls, not cryptanalytic evidence.

The [catalogue parser](catalogue_metadata/README.md), sanitized registry and
frozen indexed-cell controls remain available. Source/prior/method holds and
earlier deadline exceptions are retained. New target admission still requires
fresh exact-item evidence and feasibility strictly above 80/100; scores are
judgments, not calibrated success probabilities.
