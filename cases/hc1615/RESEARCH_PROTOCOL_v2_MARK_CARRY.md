# Method revision 1: explicit mark-preservation hypothesis

The original protocol and 22-entry baseline remain unchanged and archived. Its first lookup covers76/77 preferred units and leaves H_MARK_UNASSIGNED opaque. This method revision changes the decoder hypothesis, not the source transcription or success criteria.

For a preferred whole unit already in the byte-pinned22-entry dictionary, use its existing value. For an otherwise uncovered unit only, if its preferred baseline is in that dictionary with a single alphabetic value and its sole attached mark is a source-frozen two-stroke CARON_LIKE chevron, map the baseline and retain the caron on the resulting plaintext letter. Use explicit NFC normalization of base + U+030C. All other uncovered types stay opaque. No source position, expected word, arbitrary new letter value or dictionary refit enters the function. The existing whole-unit R_MARK value remains authoritative and takes precedence over composition.

This is a historical encoding hypothesis. The physical shape and association of the mark were observed before lookup; its plaintext diacritic function was not established by those observations. The rule was proposed after the first partial output. Root already knew the prior table and could mentally recognize the first source row from raw metadata before that output. There is no blind/held-out claim. Czech word fit may support interpretation qualitatively; it cannot prove ink, the original key or the author's intent.

Freeze the rule/config/code before the second target projection. Preserve sourcev1, the original dictionary, baseline candidate and every failed checkpoint. Record model runs separately. An independent implementation must verify all preferred unit/core/mark/event/group/row profiles and an exact forward reconstruction with source gaps/punctuation. A rule yielding natural prose is insufficient alone. Source ambiguity and all alternatives remain explicit. Re-encryption proves correspondence under this declared model, not historical uniqueness.

The release criteria stay unchanged: complete proposed reading, independent source/forward/whole-content review, exact component/event accounting and reproducible code/data. External historical confirmation and official databaseSolved status remain separate. If the rule fails, preserve the failure and continue another source; do not fit exceptions.
